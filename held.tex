\section{What this document is for}

On the first night of the hackathon, open this PDF and build only what it names.
The product is one scene. The scene is the entry.

A ward agent records that ibuprofen must be held for Patient~A, because a kidney finding and a public label say so.
The chat is cleared.
A pharmacy agent, in a new session, tries to restart ibuprofen.
FalkorDB blocks the restart and returns the path: order, hold, finding, label, prescriber, admission, policy.
Patient~B has a headache and no hold. The same restart is allowed. Patient~B is a different FalkorDB graph.

That is Held. An agent here is a function with tools. It reads the graph, takes one action, and writes the result back. It is not a personality and it is not a chatbot that happens to sit near a drawing of a graph.

\subsection{Request path}

\begin{enumerate}
  \item The page sends a pharmacy request for Patient~A, with a session id and the drug id \code{ibuprofen}.
  \item \file{src/server.ts} maps \code{patient\_a} to graph \code{held\_a}. Any other patient id returns 404 and creates no graph.
  \item \code{proposeOrder} runs \code{blockPath}.
  \item If the path has a row, the function writes an \code{Attempt} with result \code{blocked} and does not create an order. It writes a \code{HANDOFF} from the pharmacy agent to the ward agent.
  \item If the path has no row, the function creates an \code{Order} with status \code{active} and an \code{Attempt} with result \code{allowed}.
  \item The response is the decision plus the rows. The page prints them.
\end{enumerate}

Stopping FalkorDB must make \code{GET /health} return 503 and \code{proposeOrder} throw.
There is no in-memory fallback graph.

\section{Queries}

Drafts. Run each one in FalkorDB Browser before \file{src/graph.ts} calls it.
\code{WHERE} after \code{OPTIONAL MATCH} is easy to get wrong, so the block query counts the hold instead.

\subsection{\code{blockPath}}

\begin{lstlisting}
MATCH (d:Drug {id: $drug})<-[:BLOCKS]-(h:Hold)
WHERE h.invalid_at IS NULL
MATCH (h)-[:BECAUSE]->(f:Finding)
MATCH (h)-[:CITES]->(l:Label)
MATCH (h)-[:UNDER]->(p:Policy)
MATCH (f)-[:ON]->(adm:Admission)<-[:OWNS]-(prescriber:Person {role: 'prescriber'})
RETURN d.name AS drug,
       h.id AS hold,
       f.kind AS finding,
       l.sentence AS label,
       l.url AS url,
       p.text AS policy,
       prescriber.name AS prescriber,
       adm.id AS admission
\end{lstlisting}

No rows means allow. One row means block. The page prints every returned field. That printout is ``show the path.''

\subsection{\code{recordFinding}}

For \code{kind = kidney\_impairment} on \code{held\_a}, in one query batch:

\begin{enumerate}
  \item Create the finding. Link the ward agent to it with \code{RECORDED}. Link the finding to the admission with \code{ON}.
  \item Create the hold. Set \code{valid\_at} to now. Leave \code{invalid\_at} null.
  \item Add \code{BLOCKS}, \code{BECAUSE}, \code{CITES}, and \code{UNDER}. Link the ward agent to the hold with \code{WROTE}.
  \item Add a \code{HANDOFF} from the ward agent to the pharmacy agent. Reason: ``Hold written. Pharmacy must read it before a restart.''
\end{enumerate}

For \code{headache}, create the finding only. Do not create a hold.
Unknown \code{kind}: write nothing and return an error.

\subsection{\code{proposeOrder}}

\begin{enumerate}
  \item Run \code{blockPath}.
  \item Create an \code{Attempt} and \code{(attempt)-[:TRIED \{result, at\}]->(drug)}.
  \item On \code{blocked}, do not create an \code{Order}.
  \item On \code{allowed}, create an active order. The pharmacist \code{ORDERED} it, the order is \code{OF} the drug, and it happened \code{DURING} the admission.
  \item Create \code{(pharmacy)-[:HANDOFF]->(ward)} with the attempt id.
\end{enumerate}

The drug id comes from the button, which only sends \code{ibuprofen}. Reject any other drug id with 400 and write nothing.

\subsection{Concurrency check}

After the hold exists, fire two \code{proposeOrder} calls on \code{held\_a} without waiting between them.
Both results must be \code{blocked}. Both must have written an \code{Attempt}.
Neither may create an \code{Order}. Put this in \file{src/check.ts}.

\section{The check}

\code{npm run check} is one Node script. No test framework. Exit code 0 only when every step holds.

\begin{enumerate}
  \item Delete graphs \code{held\_a} and \code{held\_b} if they exist, then seed them.
  \item \code{proposeOrder('held\_a', ibuprofen)} returns \code{allowed}. Seed has an order already. This call is a second allow, before any hold.
  \item \code{recordFinding('held\_a', kidney\_impairment)} creates a hold with \code{invalid\_at} null.
  \item \code{proposeOrder('held\_a', ibuprofen)} returns \code{blocked}. The rows include Mina Cole, the policy text, and the label sentence. No new \code{Order} is created by this call.
  \item Two parallel proposes on \code{held\_a} both return \code{blocked}.
  \item \code{proposeOrder('held\_b', ibuprofen)} returns \code{allowed}.
  \item A query for a hold on \code{held\_b} returns no rows.
\end{enumerate}

If step~4 passes while Docker is stopped, delete the fallback. The last manual step, written in the README, is: stop FalkorDB, \code{GET /health} returns 503, start it, the block works again.
